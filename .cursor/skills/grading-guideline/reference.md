# iP grading bars (verbatim summary)

From https://nus-cs2103-ay2627-s1.github.io/website/admin/ip-grading.html

iP is worth 15 marks.
Meet all bars: 15.
Fall below any bar: less than half.

Grading is mostly a manual check of the final submission.
Automated dashboards help self-monitor.

## Implementation [10]

- More than 90% of all deliverables completed in the final iP.
  Requirements marked optional or if-applicable are not counted when calculating the percentage.
  When a requirement specifies a minimal version, reaching that minimal version is enough.
  Going beyond the minimal version is recommended for practice.
- Has a GUI at least as good as JavaFX tutorial part 4.
  Features covered in part 5 are not required.
- Has done at least two optional increments using AI assistance, as stated in Week 6 iP instructions.
- No major bugs.
- Reasonable use of OOP, e.g. at least some use of inheritance, with code divided into classes in a sensible way (e.g. `Ui`, `Storage`, `Parser`, `Todo`, `Deadline`, `Event`).
- At least half of the public methods/classes have Javadoc comments.
- Reasonable code quality:
  - No blatant violations of the coding standard (both Java and Git conventions).
  - The code is neat, e.g. no chunks of commented-out code.
  - Reasonable use of SLAP, e.g. no very long methods or deeply nested code.
- At least some errors are handled using exceptions.
- At least two methods have good unit tests using JUnit.

## Project Management [2]

- Submitted some deliverables in at least 4 out of the 5 iP weeks (week 2 to week 6).
- Followed the other specified requirements (e.g. using Git/GitHub for each increment and doing peer reviews) in at least 4 weeks.
- To qualify for full marks, the last 5 iP commits need to comply with the convention for Git commit message subjects (Git Standard tag green).
  If this item is not green, add more commits containing small code tweaks until the requirement is satisfied.
  Do not modify past commit messages (which requires force-pushing).

## Documentation [3]

The product website and the user guide:

- Provide enough guidance to the user.
  Cover all non-trivial features.
- No major formatting errors in the published view.
