# Seedu Git Standard

Use this skill whenever work involves a Git branch name, a commit message, or a commit review.

## Branch names

- Use a meaningful, concise kebab-case name.
- Include an issue identifier when the project workflow provides one.

## Commit subjects

- Write the subject in imperative mood.
- Capitalize the first word and do not end it with a period.
- Prefer no more than 50 characters; never exceed 72 characters.
- An optional scope or category may clarify the affected area.

## Commit bodies

- Add a body for non-trivial commits, separated from the subject by a blank line.
- Wrap body lines at 72 characters and separate paragraphs with blank lines.
- Explain what changed and why; avoid describing implementation mechanics.
- State the relevant situation, motivation, change, and rationale. Use bullets when they improve readability.

## Repository safety

- Follow the user's authorization before committing or pushing.
- Do not create a commit when the user only asks for a proposed message.

Reference: [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html)
