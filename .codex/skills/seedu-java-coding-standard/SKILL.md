# SE-EDU Java coding standard

Apply these rules whenever creating, changing, or reviewing Java code in this repository:

- Use lowercase package names, PascalCase type names, camelCase method and variable names, and SCREAMING_SNAKE_CASE constants.
- Use four spaces for indentation, K&R braces, explicit imports, and a hard line limit of 120 characters.
- Keep declarations in the smallest useful scope and use plural names for collections.
- Name boolean values and methods with prefixes such as `is`, `has`, or `can` where practical.
- Put every class in a package and always use braces for loop and conditional bodies.
- Add descriptive Javadocs to public classes and public methods, except trivial accessors, test methods, and exact overrides.
- Use `featureUnderTest_testScenario_expectedBehavior` for test method names when a descriptive name needs multiple parts.

For cases not summarized here, follow the SE-EDU Java basic and intermediate standard, then Google Java Style for uncovered topics.
