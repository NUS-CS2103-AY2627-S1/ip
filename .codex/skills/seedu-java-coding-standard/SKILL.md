# SE-EDU Java coding standard

Apply these conventions to every Java source and test edit in this project:

- Keep packages lowercase and use the project name (`friday`) as the root package.
- Use PascalCase nouns for classes, camelCase verbs for methods and variables, and
  SCREAMING_SNAKE_CASE for constants. Boolean names should read like boolean
  questions (`is...`, `has...`, `can...`). Use plural names for collections.
- Use explicit, consistently ordered imports; never use wildcard imports.
- Use four-space indentation, K&R braces, spaces around operators and keywords,
  braces for every loop and conditional, and lines no longer than 120 characters.
- Initialize variables at declaration when practical and keep them in the smallest
  scope. Preserve encapsulation by avoiding public mutable fields.
- Write descriptive Javadoc for public classes and methods (except documented
  getters/setters, inherited overrides, and test code). Keep comments in English
  with American spelling.

For details or rules not listed here, consult the
[SE-EDU Java coding standard](https://se-education.org/guides/conventions/java/intermediate.html).
