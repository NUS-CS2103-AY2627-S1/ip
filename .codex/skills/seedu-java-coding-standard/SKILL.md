# SE-EDU Java coding standard

Use this skill whenever creating, editing, or reviewing Java production code in this project.

Follow the required basic and intermediate rules in the [SE-EDU Java coding standard](https://se-education.org/guides/conventions/java/intermediate.html). Use the Google Java Style Guide only for matters the SE-EDU guide does not cover.

Before completing Java work, check the changed code for these project-relevant rules:

- Use lower-case package names; PascalCase noun names for classes/enums; camelCase verb names for methods; camelCase variable names; and `UPPER_SNAKE_CASE` for constants.
- Give booleans names such as `isDone` or `hasTasks`, use plural names for collections, and keep variables in the smallest practical scope.
- Use four-space indentation, K&R braces, spaces around operators, and no lines over 120 characters. Wrap continuation lines for readability.
- Keep imports explicit, minimal, and consistently ordered; do not use wildcard imports.
- Use braces for every loop and conditional body, even when it contains one statement.
- Write clear English (with American spelling) comments and Javadoc. Public classes and public methods require Javadoc except getters/setters, exact overrides, and test code. Javadoc summaries start with verbs such as `Returns`, `Adds`, or `Creates`; use complete, punctuated descriptions for tags that add value.

Preserve behavior while making style changes. When a rule is unclear or conflicts with an explicit project requirement, follow the project requirement and mention the conflict.
