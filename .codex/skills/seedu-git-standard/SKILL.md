# SE-EDU Git Standard

Apply this skill whenever a commit message is proposed or created.

- Write a clear subject line in the imperative mood, capitalize its first letter, omit the final
  period, and keep it preferably within 50 characters (hard limit: 72). An optional scope or
  category may precede the subject when useful.
- Use a body for non-trivial commits. Separate it from the subject with a blank line, wrap it at
  72 characters, and use blank lines between paragraphs.
- Explain what changed and why it changed, not how the diff implements it. Describe the current
  situation in present tense, the reason for the change, and the intended change in imperative
  mood. Split unrelated changes into separate commits.
- Before committing, review the staged diff and verify that the message accurately describes the
  complete commit and follows these rules.

Use the SE-EDU Git conventions as the authority for details not listed here:
https://se-education.org/guides/conventions/git.html
