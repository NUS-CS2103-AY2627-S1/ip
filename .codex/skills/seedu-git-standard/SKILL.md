# SE-EDU Git Standard

Use this skill whenever you suggest, create, review, or validate commits or
branch names in this repository.

The source of truth is the SE-EDU Git conventions page:
[Git conventions](https://se-education.org/guides/conventions/git.html)

## Commit messages

- Write a clear subject line in imperative mood.
- Capitalize the first letter of the subject line.
- Do not end the subject line with a period.
- Keep the subject line within the SE-EDU limits:
  prefer 50 characters and do not exceed 72 characters.
- Add a body for non-trivial commits.
- Separate the subject from the body with a blank line.
- Wrap commit-message body lines at 72 characters.
- Use the body to explain what changed and why, not how.
- Use blank lines between paragraphs, and use bullets when that improves
  readability.

## Branch names

- Use meaningful kebab-case branch names.
- If a branch is tied to an issue, use the format
  `issueNumber-some-keywords-from-issue-title`.

## Working style

- When proposing a commit message, prefer a subject plus body when the change
  is not trivial.
- When creating a commit, make sure the final message follows the subject and
  body rules above.
- When naming or suggesting a branch, prefer concise, descriptive keywords over
  vague names.
