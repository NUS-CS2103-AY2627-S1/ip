# SE-EDU Git Standard

Follow the project checklist in [references/git-conventions.md](references/git-conventions.md) whenever planning a commit, drafting a commit message, creating a commit, or naming a branch.

Treat the [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html) as authoritative.

## Workflow

1. Review the relevant diff and separate unrelated changes into logical commits.
2. Read the checklist before proposing a branch name or commit message.
3. Draft the complete commit message, including a body for every non-trivial commit.
4. Check the subject and every body line against the documented length limits.
5. Explain what the commit changes and why; leave implementation details to the diff.
6. Follow the repository's approval, visualization, commit, push, and merge requirements in `AGENTS.md`.

Do not treat approval to edit files as approval to commit, push, merge, delete branches, or rewrite history. Obtain authorization at the point required by `AGENTS.md`.
