# SE-EDU Git standard

Use this skill whenever creating a branch or proposing, creating, or reviewing a commit in this project.

## Branches

- Use meaningful branch names in kebab case, preferably using relevant keywords.

## Commit subjects

- Write a clear subject in the imperative mood, with a capitalized first letter and no trailing period.
- Prefer 50 characters or fewer; never exceed 72 characters.
- Add a concise scope or category prefix only when it improves clarity.

## Commit bodies

- Give non-trivial commits a body separated from the subject by a blank line, with lines wrapped at 72 characters.
- Explain what changed and why; do not explain how the diff implements it.
- Describe the current situation, why it needs to change, what to do, and why that approach is appropriate. Use blank lines between paragraphs and bullet points when useful.

For details and examples, consult the [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html).
