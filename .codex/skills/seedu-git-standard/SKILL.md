# SE-EDU Git Standard

Use this skill whenever proposing or creating a commit in this project. It
applies the [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html).

## Commit-message rules

- Write an imperative subject, capitalize its first letter, omit a final
  period, and aim for 50 characters (never exceed 72). A focused scope or
  category prefix is optional when it adds clarity.
- Give non-trivial commits a body separated from the subject by a blank line.
  Wrap body lines at 72 characters and use paragraphs or bullets when useful.
- Explain what changed and why it matters; leave implementation details to the
  diff. Describe the existing situation in present tense and the proposed
  change in imperative mood.
- Prefer cohesive, small commits. Split a commit when its explanation becomes
  too broad.

Following these message rules does not authorize committing, pushing, or any
other remote action; obtain the user's explicit approval first.
