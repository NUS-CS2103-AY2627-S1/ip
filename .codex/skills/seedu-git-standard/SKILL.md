# SE-EDU Git standard

Apply the [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html) whenever creating or proposing
commits or branches in this project.

## Commit messages

- Write a clear subject in imperative mood, capitalize its first letter, and omit a final period.
- Prefer a subject of 50 characters or fewer; never exceed 72 characters. An optional scope or category may precede it.
- For non-trivial commits, add a body separated by a blank line and wrap it at 72 characters.
- Use the body to explain what changed and why, in present tense for the situation and imperative mood for the change;
  do not explain implementation details that the diff already shows.
- Use blank lines between body paragraphs and bullets where they improve readability.

## Branch names

- Use meaningful kebab-case branch names, such as `refactor-ui-tests`.
- For issue work, use `<issue-number>-<keywords-from-issue-title>`.

Before creating a commit, check the subject length, mood, capitalization, punctuation, and body structure against this
checklist. Do not commit or push unless the user explicitly requests it.
