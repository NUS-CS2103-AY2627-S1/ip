# Seedu Git Standard

Apply the [SE-EDU Git conventions](https://se-education.org/guides/conventions/git.html) to every future commit in this repository.

- Use a concise subject line in imperative mood, starting with a capital letter and without a final period. Aim for 50 characters and never exceed 72.
- Add a blank line followed by a body for non-trivial commits. Wrap body lines at 72 characters and explain what changed and why; do not restate implementation details that the diff already shows.
- Use clear, meaningful branch names in kebab-case. Preserve a course-required branch name exactly when the assignment specifies one.
- Review the staged diff before committing so the message accurately describes the committed change.

This skill guides Git wording and review only. It does not authorize a commit, push, tag, merge, or other Git mutation; obtain the user's requested authority for those actions.
